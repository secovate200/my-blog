# SECOVATE200 Blog 유즈케이스

## 1. 액터

| 액터 | 설명 |
|---|---|
| 방문자 | 공개 블로그를 열람하고 문의하거나 회원가입을 신청하는 사용자 |
| 가입 대기 사용자 | 회원가입은 완료했지만 관리자 승인을 기다리는 사용자 |
| 일반 회원 | 승인 후 Dashboard에 로그인할 수 있는 사용자 |
| 프로젝트 구성원 | 배정된 연구 프로젝트와 연구 게시글을 관리하는 사용자 |
| 최고 관리자 | 회원 승인, 일반 게시글, 문의 답변 및 전체 관리 기능을 사용하는 사용자 |
| 외부 서비스 | SMTP 서버와 Discord Webhook |

## 2. 공개 블로그

### UC-01 공개 게시글 목록 조회

- 액터: 방문자
- 선행조건: 공개 상태의 게시글이 존재한다.
- 기본 흐름:
  1. 방문자가 블로그 홈에 접속한다.
  2. 시스템이 최신 공개 게시글을 페이지 단위로 조회한다.
  3. 제목, 카테고리, 태그, 작성일과 요약을 표시한다.
  4. 방문자는 다음 또는 이전 페이지로 이동한다.
- 예외 흐름: 게시글이 없으면 빈 상태 안내를 표시한다.
- 완료조건: 비공개 또는 임시 저장 게시글은 노출되지 않는다.

### UC-02 게시글 검색 및 필터링

- 액터: 방문자
- 기본 흐름:
  1. 방문자가 검색어를 입력한다.
  2. 시스템이 제목, 본문, 카테고리와 태그에서 검색한다.
  3. 검색 조건과 일치하는 공개 게시글만 표시한다.
  4. 방문자는 카테고리 또는 태그를 이용해 결과를 좁힌다.
- 예외 흐름: 결과가 없으면 검색 결과 없음 안내를 표시한다.
- 완료조건: 검색어를 변경하거나 초기화해도 새로고침 없이 결과가 갱신된다.

### UC-03 공개 게시글 상세 조회

- 액터: 방문자
- 선행조건: 공개 게시글이 존재한다.
- 기본 흐름:
  1. 방문자가 게시글을 선택한다.
  2. 시스템이 Editor.js 본문 블록을 렌더링한다.
  3. H1~H3 기준 목차를 표시한다.
  4. 이미지, 영상, 링크 카드, 표, 코드와 첨부파일을 표시한다.
  5. 방문자는 목차로 이동하거나 첨부파일을 내려받는다.
- 예외 흐름:
  - 존재하지 않는 게시글이면 찾을 수 없음 화면을 표시한다.
  - 첨부파일 실파일이 없으면 404를 반환한다.
- 완료조건: 안전하지 않은 HTML과 URL은 실행되지 않는다.

### UC-04 문의 등록

- 액터: 방문자
- 연동 액터: SMTP, Discord
- 기본 흐름:
  1. 방문자가 이름, 이메일과 문의 내용을 입력한다.
  2. 시스템이 입력값을 검증하고 문의를 DB에 저장한다.
  3. HTTP 응답은 외부 알림 전송을 기다리지 않고 완료된다.
  4. 백그라운드 작업이 관리자 Discord 알림과 문의 접수 이메일을 전송한다.
- 예외 흐름:
  - 입력값이 유효하지 않으면 저장하지 않고 오류를 표시한다.
  - 외부 전송이 실패해도 저장된 문의는 유지하고 실패 로그를 남긴다.
- 완료조건: 동일 IP 또는 사용자에 대한 요청 제한이 적용된다.

### UC-05 회원가입 신청

- 액터: 방문자
- 연동 액터: Discord
- 기본 흐름:
  1. 방문자가 이름, 이메일과 비밀번호를 입력한다.
  2. 시스템이 이메일 중복과 비밀번호 정책을 검사한다.
  3. 비활성 또는 승인 대기 상태의 계정을 생성한다.
  4. 관리자 승인 요청을 Discord로 전송한다.
  5. 승인 대기 안내를 표시한다.
- 예외 흐름: 중복 이메일 또는 취약한 비밀번호이면 계정을 생성하지 않는다.
- 완료조건: 관리자 승인 전에는 Dashboard 로그인이 불가능하다.

## 3. 인증 및 계정

### UC-06 로그인 및 로그아웃

- 액터: 일반 회원, 프로젝트 구성원, 최고 관리자
- 기본 흐름:
  1. 사용자가 계정과 비밀번호를 입력한다.
  2. 시스템이 자격 증명과 승인 상태를 검사한다.
  3. 세션을 생성하고 권한에 맞는 Dashboard를 표시한다.
  4. 사용자가 로그아웃하면 세션을 종료한다.
- 예외 흐름:
  - 잘못된 자격 증명이면 로그인하지 않는다.
  - 승인 대기 또는 거절 계정이면 상태별 안내 화면을 표시한다.
- 완료조건: 로그아웃 후 보호 API와 Dashboard에 접근할 수 없다.

### UC-07 비밀번호 변경

- 액터: 로그인 사용자
- 선행조건: 사용자가 로그인되어 있다.
- 기본 흐름:
  1. 설정 화면에서 변경할 수 없는 이메일을 확인한다.
  2. 현재 비밀번호와 새 비밀번호를 입력한다.
  3. 시스템이 현재 비밀번호, 확인값과 정책을 검증한다.
  4. 비밀번호를 변경하고 현재 로그인 세션을 유지한다.
- 예외 흐름: 현재 비밀번호 오류, 확인 불일치 또는 정책 위반을 표시한다.
- 완료조건: 기존 비밀번호로는 로그인할 수 없고 새 비밀번호로 로그인할 수 있다.

### UC-08 회원가입 승인

- 액터: 최고 관리자
- 연동 액터: SMTP
- 선행조건: 승인 대기 사용자가 존재한다.
- 기본 흐름:
  1. 관리자가 Django Admin에서 사용자를 확인한다.
  2. 계정 상태를 승인으로 변경한다.
  3. DB 트랜잭션이 성공한 후 승인 안내 이메일을 백그라운드로 전송한다.
  4. 승인된 사용자는 Dashboard에 로그인한다.
- 예외 흐름: 이메일 전송 실패 시 승인 상태는 유지하고 실패 로그를 남긴다.
- 완료조건: 중복 저장으로 승인 이메일이 반복 전송되지 않는다.

## 4. 게시글 관리

### UC-09 Dashboard 게시글 검색

- 액터: 로그인 사용자
- 기본 흐름:
  1. 사용자가 Dashboard 검색창에 검색어를 입력한다.
  2. 시스템이 제목, 본문, 카테고리와 태그에서 검색한다.
  3. 사용자가 열람할 권한이 있는 게시글만 표시한다.
  4. 검색어를 변경하면 목록이 즉시 갱신된다.
- 완료조건: 연속 검색이 새로고침 없이 반복 동작한다.

### UC-10 일반 게시글 작성 및 임시 저장

- 액터: 게시글 추가 권한 사용자
- 기본 흐름:
  1. 사용자가 제목, 카테고리, 태그와 공개 상태를 입력한다.
  2. Editor.js에서 필요한 블록을 추가한다.
  3. 시스템이 본문을 JSON으로 저장하고 서버에서 정제한다.
  4. 임시 저장이면 Dashboard에서만 조회한다.
  5. 공개 상태이면 공개 블로그 목록과 상세 화면에 노출한다.
- 지원 블록:
  - 텍스트, H1~H6, 글머리 목록, 번호 목록, 체크리스트
  - 인용, 표, 경고, 코드, 구분선
  - 영상, 링크 카드, 이미지, 첨부파일
- 지원 인라인 서식: 굵게, 기울임, 링크, 형광펜, 밑줄, 인라인 코드
- 예외 흐름: 필수값 또는 Editor.js 저장에 실패하면 제출하지 않고 오류를 표시한다.
- 완료조건: 저장 후 다시 편집해도 블록과 서식이 유지된다.

### UC-11 게시글 수정 및 삭제

- 액터: 변경 또는 삭제 권한 사용자
- 선행조건: 대상 게시글이 존재한다.
- 기본 흐름:
  1. 사용자가 게시글 상세에서 수정을 선택한다.
  2. 기존 Editor.js 데이터가 편집기에 복원된다.
  3. 변경 내용을 저장하면 목록과 상세 화면이 갱신된다.
  4. 삭제 권한 사용자는 게시글을 삭제할 수 있다.
- 예외 흐름: 권한이 없거나 대상이 사라졌으면 403 또는 404를 반환한다.
- 완료조건: 다른 사용자의 권한 밖 게시글을 변경하거나 삭제할 수 없다.

### UC-12 이미지 및 파일 관리

- 액터: 게시글 작성 권한 사용자
- 기본 흐름:
  1. 사용자가 이미지 또는 허용된 파일을 선택한다.
  2. 시스템이 확장자, MIME 유형과 용량을 검사한다.
  3. 파일을 미디어 저장소에 저장하고 상대 URL을 반환한다.
  4. 이미지 또는 첨부 블록을 본문에 저장한다.
  5. 상세 화면에서 이미지 표시 또는 파일 다운로드를 수행한다.
- 예외 흐름:
  - 허용되지 않은 형식이나 제한 초과 파일은 거부한다.
  - DB 레코드와 실파일이 불일치하면 500 대신 404를 반환한다.
- 완료조건: Docker 내부 호스트명이 브라우저 URL에 노출되지 않는다.

## 5. 연구 프로젝트

### UC-13 프로젝트 및 구성원 관리

- 액터: 최고 관리자
- 기본 흐름:
  1. 관리자가 프로젝트를 생성한다.
  2. 사용자 검색을 통해 프로젝트 구성원을 지정한다.
  3. 구성원별 프로젝트 접근 권한을 저장한다.
- 완료조건: 구성원이 아닌 사용자는 비공개 프로젝트를 조회하거나 변경할 수 없다.

### UC-14 연구 게시글 관리

- 액터: 프로젝트 구성원, 최고 관리자
- 선행조건: 사용자가 프로젝트 구성원이다.
- 기본 흐름:
  1. 사용자가 자신의 프로젝트를 선택한다.
  2. 연구 게시글을 작성하거나 수정한다.
  3. 기본적으로 비공개 상태로 저장한다.
  4. 필요하면 연구 문서를 PDF로 내려받는다.
- 예외 흐름: 프로젝트 권한이 없으면 403을 반환한다.
- 완료조건: 비공개 연구 내용과 첨부파일이 권한 없는 사용자에게 노출되지 않는다.

## 6. 문의 관리

### UC-15 문의 확인 및 답변

- 액터: 최고 관리자
- 연동 액터: SMTP
- 선행조건: 문의가 저장되어 있다.
- 기본 흐름:
  1. 관리자가 Django Admin에서 문의를 확인한다.
  2. 답변을 작성하고 저장한다.
  3. DB 트랜잭션 완료 후 답변 이메일을 백그라운드로 전송한다.
  4. 전송 성공 후 문의 상태, 답변자와 발송 시간을 갱신한다.
- 예외 흐름: 이메일 전송 실패 시 답변 완료로 처리하지 않고 재처리 가능한 상태를 유지한다.
- 완료조건: Admin 응답이 이메일 전송 시간 때문에 지연되지 않는다.
